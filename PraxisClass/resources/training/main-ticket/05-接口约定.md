# 教学产品资料问答接口约定

材料编号：CONTRACT-MAIN｜版本：1.0｜日期：2026-09-13  
适用产品：TICKET-DEMO 2.0｜用途：师生共用  
这是AI辅助编制的教学契约，不是真需实创已部署的API，也不表示已经运行了Spring服务。

## 1. 请求

方法与路径：`POST /api/product-qa`。媒体类型：`Content-Type: application/json`。

| 字段 | 类型 | 要求 |
|---|---|---|
| productId | 字符串 | 必填，去除首尾空白后非空；主例为TICKET-DEMO |
| productVersion | 字符串 | 必填，去除首尾空白后非空；主例为2.0 |
| question | 字符串 | 必填，去除首尾空白后非空；包含用户实际问题 |

```json
{
  "productId": "TICKET-DEMO",
  "productVersion": "2.0",
  "question": "我是管理员，怎样导出本月工单？"
}
```

JSON属性顺序不影响含义。账号角色取自本题给定条件或question中的陈述，不新增必填role字段；用户自述角色不等于真实身份鉴权。本任务不执行任何导出操作。

## 2. 请求已成功处理的响应

HTTP状态为200，响应包含以下字段：

| 字段 | 含义 |
|---|---|
| status | 本契约的业务处理结果 |
| answer | 给用户的回答、澄清问题或资料不足说明 |
| sources | 支撑结论的段落引用数组；每项含documentId与sectionId |

业务status可取三个值：

- `answered`：资料支持所给内容。
- `need_clarification`：关键业务条件未知，需先向用户补问。
- `insufficient_evidence`：已经成功读取本题指定资料，但不能据此确认问题。

有依据的响应示例：

```json
{
  "status": "answered",
  "answer": "管理员进入工单列表，将日期范围设为本月，再选择导出CSV，可导出该范围内的工单记录。",
  "sources": [{"documentId": "D1", "sectionId": "4.1"}]
}
```

关键条件未知的响应示例：

```json
{
  "status": "need_clarification",
  "answer": "请说明账号是管理员还是普通成员。",
  "sources": []
}
```

资料不足的响应示例：

```json
{
  "status": "insufficient_evidence",
  "answer": "当前资料无法确认这项功能，需要补充适用于所问产品版本的相关说明。",
  "sources": []
}
```

HTTP 200不能单独证明某个产品结论有充分依据。sources非空也不能单独证明引用正确，还要检查对应内容是否适用并支持回答。

## 3. 输入不符合契约

JSON无法解析，或三个必填字段缺失、类型错误、仅含空白时，教学契约采用HTTP 400。例如question缺失：

```json
{
  "error": {
    "code": "invalid_request",
    "message": "缺少必填字段question。",
    "fields": ["question"]
  }
}
```

JSON本身无法解析时，fields可以为空数组，并在message说明格式问题。实际实现需要明确配置校验和错误映射；不能把这些规则归功于@RequestBody自动完成。

## 4. 资料或处理服务暂不可用

指定资料当前不可读取，或处理服务暂不可用时，教学契约采用HTTP 503：

```json
{
  "error": {
    "code": "resource_unavailable",
    "message": "当前无法读取指定资料，请稍后重试。"
  }
}
```

此时没有完成资料判断，不能把它说成“已查阅资料但没有依据”。页面显示错误说明及重试入口，不从不存在的answer字段渲染成功回答。

## 5. 前后端如何对应

页面问题文本 → 请求体question → 后端接收对象的question字段。  
后端处理结果 → 响应status、answer、sources → 页面处理提示、回答和来源。

角色未知属于业务条件不完整；question缺失属于请求契约不完整。题目模拟的接口响应、学生提交的答案、教学平台自身的保存状态应分别记录。

技术语义参见[HTTP与Spring技术说明](02-HTTP与Spring技术说明.md)。路径、字段名、三种业务status和错误对象均由本案例定义，不是HTTP标准规定的统一业务格式。
