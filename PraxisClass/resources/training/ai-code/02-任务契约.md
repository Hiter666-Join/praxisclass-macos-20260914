# AI代码验收：任务契约

材料编号：CODE-CONTRACT｜版本：1.0｜日期：2026-09-13  
用途：师生共用。AI辅助编制的教学任务。

## 任务背景

你收到一段待交付程序，需要决定它是否满足需求。先说明验收要求，再选择能够发现问题的测试，查看真实运行结果，最后给出接收、拒收或尚不能判断的结论。

本课面向程序设计岗位，适合已会Python基础语法、循环与列表的学生。它是主案例之外的软件工程深度训练，不虚构新的企业委托。本课最终只交一份“代码验收记录”。

## 函数约定

实现 `solution(nums, target)`：

- nums是按非递减顺序排列的整数列表，允许空列表、负整数和重复值。
- target是整数。
- 目标存在时，返回它第一次出现的零基下标；不存在时，返回整数-1。
- 返回布尔值不能代替整数下标。不要因为Python允许部分数值比较就把True当成下标1。
- 不要求自动排序无序输入、解析字符串、处理浮点数或返回所有匹配位置。

实际诊断输入必须符合上述契约。自填界面拟限制最多64个元素、元素与target绝对值不超过1,000,000，并核对非递减顺序、排除布尔值；这是首版界面范围，不改变原函数数学契约或固定测试集。

## 你需要留下的证据

| 部分 | 必要内容 |
|---|---|
| 契约理解 | 说明输入前提、首次位置、零基下标与不存在时的返回值 |
| 测试计划 | 至少覆盖重复目标、空列表、单元素命中、目标不存在；填写预期，并说明至少一个用例能排除什么错误 |
| 当前代码 | 代码快照、来源、修订号；注明改了什么或为何暂不修改 |
| 实际运行 | 区分公开诊断与固定套件，记录确切运行及其代码版本 |
| 验收结论 | 依据本次实际结果作出结论，说明验证范围和仍需处理的问题 |

不是全选诊断卡就自动证明会设计测试；需要正确的预期和理由。不是固定套件通过就自动证明理解契约，也不是程序失败就说明你不会验收。

## 正式成果顺序

1. 读契约、看候选代码，选择测试并填写自己的预期。
2. 按需试跑公开诊断，查看实际值；可以求助、修改或说明无需修改。
3. 运行当前代码的固定验收套件。
4. 根据该次运行填写验收结论。
5. 保存同一代码、计划、运行和结论组成的一份记录。

当前代码改变后，旧结果不能证明新代码已经通过。真正重跑产生新运行；只是保存失败后再次保存同一内容，不应重复运行或多计成果。

如果环境未就绪或固定验收中断，可以保留“尚不能判断”的故障说明，但不能说代码已通过或完整验证已完成。若有据拒收，验收判断可以成立，代码仍标为待修订。
