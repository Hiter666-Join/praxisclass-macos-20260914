# 时序互动与学生任务

材料编号：RETRY-ACTIVITY｜版本：1.0  
本文是待制作互动的操作正文，AI辅助编制；没有预填学生表现或运行结果。

## 开始前

阅读[任务契约](02-创建工单任务契约.md)，选择本轮服务端规则。页面按客户端、网络、服务端三条泳道展示；每轮服务端从空状态开始。换规则后另开一轮，不在旧工单上直接切换。

情形使用[可见信息卡](03a-可见信息与情形卡.md)。先填自己能依据当前信息作出的判断，再选择是否展开教学观察。可以先求助或先看观察，但需要如实记录，不能把已经揭示的结果当成独立推断。

## 每类情形的操作

1. 发送原操作，查看客户端目前实际收到什么。
2. 填写：现在能否确定未创建工单？依据是什么？判断时是否已展开教学观察或得到关键提示？
3. 明确下一步是重试原操作还是用户提出的新操作，为它选择标识。先预测服务端最终工单总数并说明理由。
4. 执行本次发送，比较预测与本轮事件。服务端计数只在教学观察中读取；客户端记录实际收到的响应。
5. 对V1、V2、V3分别完成验证。若修改方案，建立新版本，重新验证受影响的情形，引用对应轮次。
6. 汇总为一份重试处理设计说明。未完成可存草稿，提交时声明哪些内容已经验证。

动画结束后才发送下一步，串行只是教学交互约定，不是生产系统解决并发的办法。

## 必须留下的内容

| 内容 | 填写要求 |
|---|---|
| 初次可见信息判断 | 结论、理由、当时视图及辅导情况 |
| 我的方案 | 服务端模式；重试与新操作各自的标识规则；理由 |
| 三类验证 | 情形和轮次、预测、实际发送标识、实际事件与计数、解释 |
| 最终结论 | 是否满足同一意图避免重复与新意图允许创建；尚未覆盖什么 |

不能只交“共1张”或“都通过”。V1数量看似合适，也需要解释标识选择；V3需要核对新需求是否真的完成。

## 可选对照与边界

可以对照未去重模式、重试换标识、新操作沿用旧标识；每次对照使用新轮次。没有要求先做错，正确方案同样可以直接进入验证。

参数冲突是可展开边界说明，基本活动不要求编辑任意参数或增加必做关卡。需要时请求Agent解释同标识改变参数会发生什么。

## 证据与恢复

互动产生的事件由实际规则计算后显示。教师资料中的预期不是本次运行。平台保存失败与题目中的响应丢失要分别提示；前者未成功保存时不显示“已提交”。

已固定快照的重复保存应返回同一成果。重跑仿真产生新轮次，修改方案产生修订；不能把这些都混成“重试次数”或累加为学习进步。实际字段及接入由后续平台迭代实现。
