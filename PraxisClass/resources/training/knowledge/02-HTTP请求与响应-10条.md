## KP-001 HTTP消息的基本组成

**知识说明：**HTTP消息包含控制信息、字段和可选内容；请求描述要做什么，响应报告处理结果。

**教学用法：**让学生分别标出接口请求的动作、地址、附带信息及响应结果，用于弥补网络先修知识。

**适用边界：**此处讲请求与响应，不将其称为TCP三次握手；HTTP/1.1文本样子也不代表所有HTTP版本的传输格式。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-6)；IETF / RFC Editor；RFC 9110，2022-06；定位：§6 Message Abstraction。

## KP-002 目标URI中的路径与查询

**知识说明：**路径与查询共同参与标识目标资源；片段标识fragment不属于目标URI。

**教学用法：**对照接口地址辨认path、query和请求体，说明各项放在何处。

**适用边界：**query的业务含义由接口定义，不能笼统称为只负责筛选。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-7.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§4.2.1 http URI Scheme；§7.1 Determining the Target Resource。

## KP-003 Content-Type说明实际内容类型

**知识说明：**Content-Type指明所附表示的媒体类型。

**教学用法：**为一份JSON请求选择合适的类型声明，再检查正文是否与声明相符。

**适用边界：**它不是希望收到的响应类型；仅写application/json不会把任意文本变成合法JSON。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.3)；IETF / RFC Editor；RFC 9110，2022-06；定位：§8.3 Content-Type。

## KP-004 Accept表达响应类型偏好

**知识说明：**Accept表达客户端可接受的响应媒体类型，可带偏好权重。

**教学用法：**用“我发送什么”和“我希望收到什么”区分两个常见请求头。

**适用边界：**它不声明请求体类型，也不保证服务器一定提供该格式。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§12.5.1 Accept。

## KP-005 HTTP状态码的五类含义

**知识说明：**状态码首位划分类别：1xx信息、2xx成功、3xx重定向、4xx客户端错误、5xx服务器错误。

**教学用法：**先识别协议层结果，再阅读主案例JSON中的业务状态。

**适用边界：**2xx不证明知识回答正确，也不证明学习者已达标；两项判断均需额外证据。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§15 Status Codes；§15.1 Overview of Status Codes。

## KP-006 GET获取资源表示

**知识说明：**GET请求取得目标资源的选定表示，规范将其列为安全方法。

**教学用法：**要求学生解释查询资料与提交处理任务分别需要怎样的接口语义。

**适用边界：**安全方法描述请求意图，不保证服务器连日志等附带变化也没有。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§9.3.1 GET；§9.2.1 Safe Methods。

## KP-007 POST的资源特定处理

**知识说明：**POST要求目标资源按自身规则处理请求内容，不局限于创建资源。

**教学用法：**说明主案例为什么把问题提交到处理接口，并另读案例接口约定。

**适用边界：**方法名不能替代接口契约，也不能单凭POST就确认该操作可安全重复。

**适用案例：**Spring＋Spring AI主案例、重试与幂等。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.3)；IETF / RFC Editor；RFC 9110，2022-06；定位：§9.3.3 POST。

## KP-008 HTTP字段名不区分大小写

**知识说明：**HTTP字段名不区分大小写。

**教学用法：**比较Content-Type与content-type，再单独检查JSON属性拼写。

**适用边界：**此规则不能推广到字段值、URL路径或JSON键名；它们按各自规则处理。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§5.1 Field Names。

## KP-009 400表达请求有误

**知识说明：**400表示服务器认为请求存在客户端错误，因而不能或不愿处理。

**教学用法：**将主案例不符合输入契约的情况与资料不足分开讨论。

**适用边界：**案例把特定无效输入映射为400属于案例约定；并非所有业务失败都必须用400。

**适用案例：**Spring＋Spring AI主案例。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.1)；IETF / RFC Editor；RFC 9110，2022-06；定位：§15.5.1 400 Bad Request。

## KP-010 503表达暂时不可用

**知识说明：**503表示服务暂时无法处理请求，可通过Retry-After提示等待。

**教学用法：**区分服务不可用、资料无依据和学生作答错误，避免混成一个失败状态。

**适用边界：**具体故障是否映射503须由接口约定；收到503也不能单独证明创建操作未发生。

**适用案例：**Spring＋Spring AI主案例、重试与幂等。学习层次：基础。

**依据：**

- [H1 RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.6.4)；IETF / RFC Editor；RFC 9110，2022-06；定位：§15.6.4 503 Service Unavailable。
