## KP-033 从需求形成测试判据

**知识说明：**软件技术教学标准将按产品需求规划测试、设计用例和提交缺陷报告列为软件测试任务。

**教学用法：**先写清输入、预期结果及异常条件，再看程序实际输出；五组都可采用此顺序。

**适用边界：**标准支撑教学目标；具体预期必须来自本题契约，不能让候选代码自身决定正确答案。

**适用案例：**Spring＋Spring AI主案例、AI代码验收、重试与幂等、工业视觉质检、仓储路径与时限。学习层次：基础。

**依据：**

- [N1 软件技术专业教学标准（高等职业教育专科）](https://hudong.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/17zt06_bznr/bznr_zyjyzyjxbz/gdzyjy_zk/zk_dzyxxdl/dzxxdl_jsjl/202502/P020250207533323690137.pdf)；教育部；2025年版；专业代码510203；定位：PDF第4页，8.1.2专业课程续表，序号6软件测试。

## KP-034 用黑盒方法核验功能

**知识说明：**程序设计员职业标准要求以黑盒方法进行功能验证，并处理异常与错误返回。

**教学用法：**先依据可观察输入输出检查承诺是否成立，再分析实现细节；记录无法判断的情况。

**适用边界：**黑盒验证不意味着少量用例可证明全部正确，也不等于完成职业等级认证。

**适用案例：**Spring＋Spring AI主案例、AI代码验收、重试与幂等、工业视觉质检、仓储路径与时限。学习层次：基础。

**依据：**

## KP-035 二分定位的有序前提

**知识说明：**bisect用于有序序列，不负责先把输入排序。

**教学用法：**验收查找程序时，先检查契约是否约定非递减顺序，避免对超出约定的输入误判。

**适用边界：**如果题目未要求支持无序输入，不擅自新增无序处理必做项；比较规则也须一致。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

- [P1 Python — bisect: Array bisection algorithm](https://docs.python.org/3/library/bisect.html)；Python Software Foundation；滚动官方文档；2026-09-14核对，非项目依赖版本；定位：Array bisection algorithm；bisect_left。

## KP-036 bisect_left给出最左插入位置

**知识说明：**bisect_left返回保持有序的左侧插入点，相等元素存在时位于其最左侧。

**教学用法：**让学生比较重复值情形下的插入位置和任意一次命中位置。

**适用边界：**返回的是插入位置，即使不存在目标也有返回值，不能直接宣布查找成功。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

- [P1 Python — bisect: Array bisection algorithm](https://docs.python.org/3/library/bisect.html#bisect.bisect_left)；Python Software Foundation；滚动官方文档；2026-09-14核对，非项目依赖版本；定位：bisect_left。

## KP-037 插入位置还需验证精确命中

**知识说明：**从插入点判断精确命中时，需要同时核对下标未越界且该位置等于目标值。

**教学用法：**在查找验收中分别讨论存在目标、目标缺失和空序列，说明判断依据。

**适用边界：**题目若约定未找到返回-1，应再按该契约转换；库函数不会自动替换返回值。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

## KP-038 比较实际值与独立预期

**知识说明：**unittest的assertEqual核对两个值相等与否，失败时报告差异。

**教学用法：**先从任务契约推导预期，再与当前代码运行结果比较，并解释一处差异。

**适用边界：**断言通过只证明该次比较；本知识包没有运行当前学生代码，也未产生通过率。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

- [P2 Python — unittest: Unit testing framework](https://docs.python.org/3/library/unittest.html#unittest.TestCase.assertEqual)；Python Software Foundation；滚动官方文档；2026-09-14核对，非项目依赖版本；定位：TestCase.assertEqual。

## KP-039 subTest保留参数化诊断信息

**知识说明：**subTest为循环中的参数实例保留标识，便于分别报告失败并继续其他子测试。

**教学用法：**用不同输入说明同一个查找要求的边界，记录是哪组条件没有满足。

**适用边界：**多个子测试不自动变成多个独立测试方法；它也不增加测试集覆盖的真实范围。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

- [P2 Python — unittest: Unit testing framework](https://docs.python.org/3/library/unittest.html#distinguishing-test-iterations-using-subtests)；Python Software Foundation；滚动官方文档；2026-09-14核对，非项目依赖版本；定位：Distinguishing test iterations using subtests。

## KP-040 assertRaises核验异常类型

**知识说明：**assertRaises检查是否抛出指定异常；没有抛出或抛出其他类型会导致验证不通过。

**教学用法：**针对契约明确规定的异常写验证；区分预期异常、程序错误和执行环境故障。

**适用边界：**只检查异常类型不能证明错误消息或恢复逻辑正确；案例未要求的异常处理不新增为扣分项。

**适用案例：**AI代码验收。学习层次：基础。

**依据：**

- [P2 Python — unittest: Unit testing framework](https://docs.python.org/3/library/unittest.html#unittest.TestCase.assertRaises)；Python Software Foundation；滚动官方文档；2026-09-14核对，非项目依赖版本；定位：TestCase.assertRaises。

## KP-041 Worker承接计算以保持界面响应

**知识说明：**Pyodide可在Web Worker中执行计算，减少同步计算阻塞主界面的影响。

**教学用法：**说明浏览器运行代码时为何把计算与界面分开，帮助学生读懂执行流程。

**适用边界：**Worker不能直接操作DOM；独立线程不等于自动具备无限资源、超时终止或完整安全隔离。

**适用案例：**AI代码验收。学习层次：原理。

**依据：**
