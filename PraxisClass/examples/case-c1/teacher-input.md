# 案例 C1：校园 Python 实验室技术咨询台

这是一份由 PraxisClass 整理的教学任务输入样例，不是学校规章。技术依据为 Python 官方文档，核对日期为 2026-09-05。正式校内制度、开放时间和联系方式必须由学校另行提供；系统不能补写这些信息。

## 工作情境

你是校园 Python 实验室的助教，需要把重复出现的技术问题整理成带来源的问答。新同学经常混淆二分检索的插入点与命中位置，也不熟悉 JSON、CSV 文档导入及测试结果保存。

## 交付任务

设计一节 30 分钟实训课。学习者应完成“读取技术条目 → 检索相关依据 → 撰写带来源的答复 → 运行案例验证 → 记录失败原因”流程。面向已了解变量、列表和函数的新生。

先完成查询：“有重复值时，怎样用二分查找得到第一次出现的位置？”再处理：“JSON 导入失败应该怎样定位？”最后讨论：“若同学询问实验室周日是否开放，而知识库没有校内制度，应该如何回答？”

## 可用材料

知识资料由教师上传到自己的 Dify 知识库，应用不内置知识条目。配套 PDF 另存于工作区 output/pdf/Dify知识库资料，准确版本与来源见该目录的文件说明。当前现成中文版为《Hello 算法》1.3.0 的 Python 版，可先完成二分查找问答；JSON/CSV 排错部分需补充相应中文资料后再验收。参考页面：

- https://docs.python.org/3/library/bisect.html
- https://docs.python.org/3/library/json.html
- https://docs.python.org/3/library/csv.html
- https://docs.python.org/3/library/unittest.html
- https://docs.python.org/3/library/sqlite3.html

## 答复规范

每条答复只使用检索返回的依据，保留来源链接。插入点可能指向列表末尾，访问前必须检查边界。来源未覆盖的问题应明确“当前资料不足”，并指出需要补充哪类材料。不得编造学校事实、测试成绩或检索来源。

## 课程结构建议

1. 工作情境与交付标准，5 分钟。
2. 从问题提取关键词，检索并核对来源，5 分钟。
3. 二分检索公开案例与边界推演，10 分钟。
4. JSON 导入错误分析与回答缺少依据的问题，5 分钟。
5. 提交结果和自学反馈，5 分钟。

## 验收标准

答复正确区分插入点与命中位置；重复值场景找到左界；引用与主张对应；资料不足时不猜测；案例代码有实际运行结果。技术调试通过率与真人教学成效分别记录。教师评分与修改耗时需在实际审阅后填写。

## 在本平台中使用

教师先将配套 PDF 上传到 Dify，等待解析和索引完成，再提供知识库接入信息。应用接入后，将本稿正文粘贴到备课需求，使用知识提取控件附加检索依据，并启用产业任务转化模式查看结构化任务卡。验收时确认知识源指示为 Dify，返回内容与来源可以追溯到上传文档。模型生成需由实际模型配置完成。
