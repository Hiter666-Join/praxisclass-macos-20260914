# 真需实创

**把产业任务带进课堂，让学习在实践中发生。**

面向职业教育的教学实训智能体应用，以教师的岗位任务教学转化为主、学生的实训学习指导为辅，围绕“岗位任务 → 教学设计 → 交互实训 → 评价反馈”，把专业资料、智能体协作和课堂活动组织成可体验、可复用的教学流程。

## 场景与价值

教师准备岗位实训时，需要把企业任务拆成适合学生的学习步骤，并组织知识依据、练习与评价。学生需要在实际操作中获得提示，理解判断依据，逐步完成任务。

真需实创以“岗位典型工作任务转化成学习型任务”为主线，服务教师备课、课堂组织、学生实践和教学复盘。源码附有 Python 有序数据检索练习与技术咨询台任务素材，便于从具体案例开始体验。

## 作品亮点

- **以岗定教的任务转化**：围绕工作情境、目标、工具材料、操作步骤、判断节点与完成标准组织教学场景，把岗位要求落实为可操作的学习活动。
- **以任务资料支持教学转化**：在备课页上传岗位任务书、技术规范等材料，供智能体处理并生成教学内容，教师核对生成结果与依据；需要检索已有专业知识时，可在设置中选配 Dify。
- **分工明确的智能体协作**：在 PBL 实训中组织规划、导学、情境扮演与评价角色；课堂提供多角色讨论、共享白板和追问，连接内容呈现与实践过程。
- **能够动手的实训课堂**：融合讲解课件、交互图示、测验、代码练习和项目式学习；学生可操作、提交成果并获得反馈。
- **教师经验复用**：教师在“设置 → 记忆”保存人物画像与长期记忆，后续大纲、课件内容和讲解生成会读取相关背景；当前任务要求和已确认大纲优先，学生生成不加载教师记忆。
- **可查阅的教学 Skill 库**：设置面板展示 23 项内置技能，按教学用途分组，支持搜索、查看功效与适用场景、阅读详情和下载，覆盖课程设计、学习方法、内容核查、课件制作与经验复用。
- **贯通教与学的反馈**：教师工作台、课程管理、学生入口、学习看板和反馈表单相衔接；配套编程实训可回传测试结果，辅助按课程、版本进行复盘。
- **可编辑、可复用的成果**：支持 PPTX 导入、课件编辑、PPTX 与课堂包导出；图像、语音、语音识别和视频能力可按演示需要接入。
- **贴近课堂组织的操作入口**：课程工作台、学生课堂链接入口、课表抽屉和本地时钟，使备课、进入课堂与查看安排衔接起来。
- **适合轻量演示的模块组织**：网页、接口和平台数据由主应用承载，模型、远程解析及知识检索按需接入，减少在应用服务器上运行大型模型的需要。

Skill 面板中的“已启用”表示技能已纳入内置库，并不表示点击即可独立执行，也不表示全部技能都已自动接入普通备课链路。“教师经验复用”已接入当前备课生成流程。普通教学入口仍可使用；本内测部署包同时启用 Pro 和 PostgreSQL 共享存储，具体启动方式见外层说明。

### 智能体如何协作

| 角色 | 教学职责 | 体验时关注 |
| --- | --- | --- |
| Planner · 规划智能体 | 将项目目标拆为里程碑与微任务，组织路径和交付要求 | 任务是否有清楚的步骤和完成标准 |
| Instructor · 导学智能体 | 围绕当前任务追问、提示，结合过程观察调整引导 | 能否帮助学生解释思路并继续实践 |
| Simulator · 情境智能体 | 在情境类任务中扮演业务角色 | 是否提供岗位沟通与判断的练习情境 |
| Evaluator · 评价智能体 | 针对提交成果生成任务反馈、阶段反思和项目总结 | 评价是否对应目标并能指导修正 |

这些角色主要体现在项目式实训中；不同课堂场景按需要使用相应能力。

## 评委快速体验（远程访问）

评委访问已部署的地址无需安装 Node.js、pnpm 或 Docker。教师与学生均免密进入；需要现场生成时，在当前端填写该端自己的模型配置。源码默认不共享服务商、凭据或模型。团队提供演示地址、体验顺序及准备好的教学资源。

本文不写入私有服务器地址或模型密钥。请使用随作品单独提供的《演示访问说明》中的链接；若尚未收到，请由演示负责人补齐后访问。

建议按以下路线体验，已有课堂与现场生成均可展示：

1. **进入平台**：打开演示地址的 `/portal`，直接选择教师入口；学生入口同样免密，无需注册。
2. **提供岗位任务与依据**：进入备课页，填写具体岗位任务，按需上传任务书、技术规范或实训指导材料。
3. **查看教学转化**：进入备课页，使用具体岗位任务生成大纲，核对任务目标与练习安排，再生成课堂；也可从“课程管理”打开预置课堂。
4. **体验课堂**：切换场景，播放讲解、追问、查看白板；选择一项交互练习、测验或 PBL 任务完成操作并查看反馈。
5. **查看教师经验与技能**：在“设置 → 记忆”查看示例教学偏好，在“设置 → Skill”查看技能用途与详情。修改记忆会影响同一演示教师空间的后续备课，请按演示安排操作。
6. **切换学生视角**：回到平台入口选择学生，打开课程或使用“加入课堂”粘贴团队提供的同站课堂链接，体验学习过程。
7. **查看教学复盘**：提交一次体验反馈，进入相应学习看板；教师看板可用于查看已有课程反馈与测试记录。

开启备课页的“职教任务”后，生成编排依据实际任务、学情和所选资料决定页数、活动类型与顺序。概念讲解、示例、练习、测验、PBL、能力图谱和培养方案分析均按需使用，不强制整套流程或固定配额。岗位需求与优化建议必须有本次资料依据；缺少依据的内容保留为待教师核对的建议。关闭开关时沿用普通备课流程。

Pro 智能体维护可恢复的“当前委托”：新增要求只更新相关部分，原话和被替换的要求保留在会话记录中；讨论与审核状态不写入课程。局部修改保留有效页面。课程草稿保存、结构检查、所选互动用例执行、教师审阅及真实学生成果分别记录或展示，技术检查通过不等于教学质量或学习成效已经得到验证。缺少执行条件时保留草稿并标明未验证；观察到缺陷时只进行有限次局部修正。

生成期间请留在当前页面；第一页进入课堂后，其余页面仍可能在生成，气泡提示会持续到整门课完成。待提示消失后，再返回首页或切换课程。

现场生成会调用当前端在设置中配置的模型服务，耗时取决于内容和服务响应。建议先看已准备的课堂，再体验小规模现场生成。演示中的案例素材与测试数据用于说明流程，真实试用结果以团队另行提交的记录为准。

### 实训要求与历史示例（2026-09-14）

教师工作台以备课和已有课程为入口，五组预置案例不再作为默认制作路径。原有课程、任务链接、资料及成果保留，已知预置课程在课程详情中标明“预置示例／课程草稿”。从课程详情展开“实训要求与成果”，教师选择已有活动，填写实际任务与评阅标准，按需上传正文资料；专业和岗位默认留空。保存实训要求后学生可以提交并回看原文，这个操作不修改课堂页面，也不自动选用固定案例知识包。

历史示例继续使用共享实训服务、SQLite业务索引和PostgreSQL运行记录，需启用下文共享存储配置。代码验收还需浏览器能下载Pyodide 0.29.2。固定规则核对与 Agent 开放评阅分开；AI服务未配置或失败时，已保存原文和规则结果仍可回看。PBL 只有实际数值评分才进入通过率统计；只有文字反馈时保留评语，不再默认记为满分通过。

本包附有历史[分流程测试复现书](../docs/05-demo/测试复现书-20260914/00-复现入口与准备.md)，含可复制输入、异常恢复、实际编号与截图。其中部分步骤记录了已撤下的默认演示入口和旧知识包按钮；新版启动及操作以包外层 `README-部署.md` 为准，历史编号对应的数据不随包提供。当前证据来自本地3003环境的开发者走查，远程环境及真实目标用户反馈需分别登记。

## 本地部署（团队内测）

### 1. 准备环境与源码

使用 Node.js **22.13 或更高版本的 22.x**、pnpm **10.28.0**，并确保能够访问依赖仓库及所选 AI 服务。浏览器使用支持现代网页功能的桌面浏览器。

使用本次 Windows/macOS 包时，完整解压并按外层 `README-部署.md` 启动，默认访问 `http://127.0.0.1:3210/portal`。内置 Node.js 24.14.0 和 pnpm 10.28.0；Docker Desktop 用于本包的 PostgreSQL。以下源码命令仅供手动部署参考。

```bash
node --version
pnpm --version
```

如尚未安装 pnpm，可执行：

```bash
npm install --global pnpm@10.28.0
```

### 2. 建立自己的配置

Windows PowerShell：

```powershell
Copy-Item .env.example .env.local
```

macOS / Linux：

```bash
cp .env.example .env.local
```

仅在首次配置时复制，已有 `.env.local` 时直接编辑，避免覆盖自己的参数。浏览器端默认使用独立的教师/学生设置：供应商凭据为空、未选择模型，图像/视频生成及语音功能默认关闭。进入对应端的“设置”后自行配置供应商、地址、凭据和模型，修改会持久保存；不会自动套用另一端或环境变量里的模型配置。“系统设置 → 恢复本端基础配置”恢复同一套源码默认值，保留课程、测试记录和另一端设置。完整部署变量见 [`.env.example`](.env.example)。

以下环境变量仅作为服务器任务与部署配置示例，浏览器端的供应商设置仍需在各端面板填写；占位文字必须换成实际值：

```env
OPENAI_API_KEY=YOUR_API_KEY
OPENAI_BASE_URL=https://YOUR_API_HOST/v1
OPENAI_MODELS=YOUR_MODEL_ID
DEFAULT_MODEL=openai:YOUR_MODEL_ID

PRAXIS_ENABLE_VOCATIONAL=true
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true
NEXT_PUBLIC_PRAXIS_EDITOR_ENABLED=true
NEXT_PUBLIC_PRO_WORKBENCH_ENABLED=true
```

使用其他内置提供商时，改填该提供商的变量与 `提供商:模型名称`。模型 API 密钥仅用于当前端的服务配置。讯飞星火 HTTP 模型使用对应版本的 APIPassword；讯飞语音合成另用同一应用的 APPID、APIKey、APISecret，不能混用。

未配置远程解析、Dify、图像或视频时，先验证文字备课及已有课堂即可；需要体验相应能力时，再按[可选能力配置](#可选能力配置)补齐。

### 3. 安装并启动

```bash
pnpm install --frozen-lockfile
pnpm dev
```

首次安装会通过 `postinstall` 构建本仓库内的课件相关包并同步导入器资源。请保留安装脚本执行，不使用 `--ignore-scripts` 跳过该步骤。

访问 `http://localhost:3000/portal`，选择教师或学生入口即可免密进入，无需注册。根据企业教师对 Demo 的要求，2026-09-14 起取消教师 PIN 和整站访问码；旧环境中的 `TEACHER_PIN`、`ACCESS_CODE` 不再触发口令校验。角色各自的服务设置、任务归属与学生记录范围仍分别处理。PowerShell 若提示脚本执行策略阻止 pnpm，可把命令中的 `pnpm` 写成 `pnpm.CMD`。

端口被占用时可执行 `pnpm dev --port 3210`，访问 `http://localhost:3210/portal`。后续尽量使用同一个主机名与端口，浏览器本地课堂数据按站点来源保存。

停止运行：在启动终端按 `Ctrl+C`。再次体验：回到源码目录运行 `pnpm dev`，无需每次重新安装。

### 4. 本机构建运行（可选）

需要以构建后的方式内测时，先停开发服务，再执行：

## 完整使用指南

### 教师入口与课程管理

从 `/portal` 进入教师模式，工作台 `/teacher` 汇总课程与教学入口；`/teacher/courses` 管理并进入现有课堂，`/` 为备课页。首次运行没有个人课堂是正常状态，可以生成课堂或导入案例包。

### 上传任务资料与可选 Dify 接入

主演示流程在备课页直接上传岗位任务书、技术规范和实训资料，再生成大纲与课堂。文件上传与解析独立于 Dify，不需要先建立本地知识库；支持的格式和容量以当前上传控件为准。

需要体验远程知识检索时，在教师端“设置 → Dify 接入”填写 API 地址、数据集 ID 和知识库 API 密钥，测试连接后打开 Dify 检索页。可查看远端文档状态、检索依据，并把选中的知识点带入备课。知识库的上传、整理与索引在 Dify 中完成。

当前 Demo 已移除本地知识库的资料管理、入库发布、案例筛选与本地检索回退。未配置 Dify 不影响普通备课及文件上传；Dify 不可用时会明确提示。升级不会删除已有本地资料或远端 Dify 文档，但旧本地管理接口已停用。

若视频展示了预配置 Dify 的完整流程，而在线 Demo 需要自行接入，请在随作品交付的访问说明中明确两者的体验范围。

### 岗位任务 → 大纲 → 课堂

1. 在备课页输入具体岗位任务，包含学生基础、课时、交付成果和评价标准；按需选择知识库案例或添加资料。
2. 需要展示岗位任务引擎时，启用已配置的相关选项；需要练习时选择合适的互动或实训场景。
3. 发起生成后检查大纲，调整场景顺序、知识要点与练习要求，再确认生成。
4. 生成完成进入课堂，逐页检查讲解、图片、互动和题目。教师可进入编辑并修改课件。
5. 返回课程管理再次打开，确认成果可复用；重要内容及时导出课堂包。

可直接试用的任务示例：

> 面向已学习 Python 循环和列表的高职学生，把“为仓储系统实现有序商品编号检索”转化为一节 20 分钟实训。要求解释二分检索的适用条件，编写检索函数，处理空列表、未找到和边界值，通过测试后说明时间复杂度。安排讲解、区间可视化、代码练习与反思，以代码正确性、边界处理和解释清晰度评价。

这是建议输入的教学示例，生成结果需要教师核对。

### 课堂互动与学生实训

- 使用场景导航进入讲解、测验、交互或 PBL 场景；播放/暂停讲解，根据场景使用追问、讨论和白板。
- 在代码或交互练习中实际操作，查看运行结果与提示；在 PBL 中围绕任务推进、提交成果并阅读评价。
- 学生从 `/student` 选择课程，或点击“加入课堂”，粘贴当前服务器的 `/classroom/课堂ID` 链接。此入口只接受同站课堂地址。
- 学生在 `/student/dashboard` 查看当前学习者相关记录；教师从 `/dashboard` 查看教学汇总。反馈提交后刷新相应看板查看变化。
- 课堂中的“课表”打开侧边抽屉；时钟显示访问者设备的本地时间与时区，用于课堂节奏参考。

课堂链接能否在另一台电脑打开，取决于课程是否存入共享后端；仅复制本地课堂 URL 不会把浏览器中的内容传到服务器。

### 教师记忆与 Skill

1. 以教师模式进入“设置 → 记忆”，填写人物画像（如专业、教学对象）和长期记忆（如偏好先练后讲、重视边界测试）。
2. 保存后重新打开，确认内容已持久化。
3. 用一个新任务生成大纲和课堂，核对相关偏好是否合理体现。明确写入本次任务的要求优先于历史偏好。
4. 在“设置 → Skill”按教学用途浏览或搜索技能，打开详情了解适用场景，按需下载。

当前 Demo 使用单一教师记忆空间，供团队演示与内测；学生生成请求不读取这份教师记忆。生成流程不会自动改写记忆或另建个人 Skill。

### 课表、复盘与成果导出

在 `/schedule` 创建或编辑教学安排，核对标题、时间、重复规则与启用状态。课堂内也能查看课表；平台服务需保持运行才能处理服务端安排。

体验结束提交反馈，再查看相应看板；代码案例可演示测试结果回传。反馈、测试记录与 AI 评价分别反映体验、运行表现与模型分析，解读时结合具体任务。

备课页支持导入已有课堂包；启用 PPTX 导入后可导入 PPTX 继续编辑。课堂导出菜单可用于保存课堂包或 PPTX，保留可再次使用的教学成果。语音、图像、视频生成及 MP4 导出由对应服务配置决定；MP4 渲染部署见 [render-service/README.md](render-service/README.md)。

### 使用附带编程案例

安装依赖后，在源码根目录执行：

```bash
node scripts/build-case-a-demo.mjs ./demo-output
```

在备课页导入 `demo-output` 中生成的 `.praxis.zip` 课堂包。该案例包含 12 条固定测试用例、分层提示和区间可视化，可体验“编写 → 运行 → 查看反馈”。这是运行时生成教学案例文件，不是本次发行源码的压缩打包。

## 服务器部署（供部署负责人使用）

主服务集成网页、接口和平台数据，模型及知识服务通过 API 接入。评委使用远程链接，无需执行本节命令。

### 1. 配置应用

将整个 `PraxisClass` 源码目录上传到服务器，准备 Docker 与 Compose，在源码根目录创建 `.env.local`，填写本地部署章节中的模型与教学开关。Demo入口统一免密，无需配置教师口令。

服务器部署建议通过团队配置的 HTTPS 域名访问。若临时使用 `http://服务器地址:3000/portal`，需按实际网络环境放行应用端口。麦克风等浏览器能力应在 HTTPS 或 localhost 环境体验。

### 2. 为跨电脑访问启用共享课堂

评委从自己的浏览器访问预置课程时，使用 Compose 的 `server-persistence` profile，并在 `.env.local` 配置：

```env
PERSISTENCE_POSTGRES_PASSWORD=YOUR_DATABASE_PASSWORD
DATABASE_URL=postgres://praxis:YOUR_DATABASE_PASSWORD@postgres:5432/praxis
PERSISTENCE_DEV_TOKEN=YOUR_DEMO_SHARED_TOKEN
NEXT_PUBLIC_PERSISTENCE=1
NEXT_PUBLIC_PERSISTENCE_TOKEN=YOUR_DEMO_SHARED_TOKEN
```

数据库密码与连接串一致；密码含 URL 保留字符时须在连接串中编码。两个 Token 必须相同。这里的共享 Token 是 Demo 共享机制，会用于浏览器请求，不应当作正式用户隔离或生产认证方案。

```bash
docker compose --env-file .env.local --profile server-persistence up -d --build
```

只需要单一浏览器临时演示时，也可不启用共享配置，使用：

```bash
docker compose --env-file .env.local up -d --build
```

访问 `/portal`。共享部署完成后，在该服务器的教师端重新导入演示课堂或生成课程；已有本地浏览器数据不会因开启共享开关自动变成服务器预置内容。然后用另一浏览器实际打开课堂链接确认。

可按需配置 `NEXT_PUBLIC_STUDENT_COURSE_IDS=课堂ID1,课堂ID2` 固定学生入口展示的课程。该参数只指定入口，课程内容必须已经存在于共享后端。

`NEXT_PUBLIC_*` 为构建期参数，改动后重新构建镜像。`docker-compose.agent-local.yml` 是本地数据库调试覆盖文件，常规服务器演示使用上面给出的主 Compose 命令即可。

### 3. 可选能力配置

| 能力 | 配置或操作 |
| --- | --- |
| Dify 专业知识库（可选） | 教师端“设置 → Dify 接入”；或部署者配置 `DIFY_BASE_URL`、`DIFY_DATASET_ID`、`DIFY_DATASET_API_KEY`，使用知识库 API 密钥 |
| MinerU 云端解析 | `PDF_MINERU_CLOUD_API_KEY`、`PDF_MINERU_CLOUD_BASE_URL`，页面选择对应解析服务 |
| 自建 MinerU / 阿里文档解析 | 按 `.env.example` 填写该解析器配置，再在页面选择；云端解析会将所选资料发送到所配置服务 |
| 讯飞语音合成 | 同一应用的 `TTS_XFYUN_APP_ID`、`TTS_XFYUN_API_KEY`、`TTS_XFYUN_API_SECRET`，并选择已开通音色 |
| 其他语音、图像、视频、搜索 | 配置相应提供商服务端变量，在设置中选择可用服务 |
| MP4 导出 | `NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true`，额外启用 `video-export` profile；独立渲染服务较重，资源要求见其 README |
| Demo 入口 | 教师与学生统一免密进入；无需教师 PIN、整站访问码或注册 |

内网自建服务按 `.env.example` 的网络访问说明配置，不要将服务商密钥放到 `NEXT_PUBLIC_*` 中。轻量演示服务器可以先启用文本、课堂和远程知识能力，再按资源条件选择媒体服务。

### 4. 日常维护与数据

```bash
docker compose --env-file .env.local --profile server-persistence ps
docker compose --env-file .env.local --profile server-persistence logs --tail 100 praxis
```

更新源码或构建期配置后，重新执行带 `--build` 的启动命令。停止整套服务可以使用相同 profile 的 `down`；保留数据时不要加 `-v`。

| 数据 | 默认位置 / 处理方式 |
| --- | --- |
| 本地课堂与浏览器偏好 | 当前浏览器站点存储；重要课堂用导出功能备份，清理浏览器数据会影响本地内容 |
| 平台反馈、课表、知识资料、记忆 | 本地默认为 `data/`，可由 `PLATFORM_DATA_DIR` 指定；Docker 使用 `praxis-data` 卷 |
| 开启共享后的课堂等持久化数据 | PostgreSQL；Compose 使用 `praxis-postgres` 卷，备份时一并保留 |
| 模型密钥和部署参数 | 部署者自己的 `.env.local`，独立保存，不随源码提交 |

更新前备份平台数据、共享数据库和重要课堂导出文件。不要只备份源码便认为已备份课程与知识资料。

### 演示交付检查

- 打开 `/api/health`、`/api/stages`、`/portal`，确认共享存储可用，教师与学生均能免密进入。
- 用第二个浏览器进入教师与学生入口，实际打开预置课堂，确认共享内容和媒体能够读取。
- 以小任务完成“上传任务资料、生成大纲、核对内容与依据、生成课堂”；若展示 Dify，另行验证连接、检索命中及知识点带入备课。
- 实际完成一次互动或测试、提交反馈并在看板查看。
- 提供远程入口、免密角色选择方式、预置课堂链接、建议体验顺序和联系人；模型服务仍由各角色自己的设置提供。

源码中的 `pnpm platform:preflight` 可用于服务已启动后的基础探测，默认访问 `http://localhost:3000`，也可用环境变量 `BASE_URL` 指向目标地址。它检查免密入口，不等价于用户走查，也不输出含口令的链接。

## 内测记录与常见问题

团队内测建议至少记录：系统与浏览器、发行标识、使用入口、任务输入、操作步骤、预期结果、实际结果和必要截图。涉及模型调用时补充提供商与模型名称，记录中不包含 API 密钥或访问口令。

| 现象 | 处理方法 |
| --- | --- |
| `node:sqlite` 不可用 | 检查启动终端实际使用的 Node 版本，要求 22.13+ |
| 安装后提示工作区包或导入器资源缺失 | 确认第一次安装未跳过脚本；可执行 `pnpm run postinstall` 重新构建内部包，再启动 |
| 页面可打开但生成失败 | 检查提供商、模型名称、密钥、额度与网络，确认 `DEFAULT_MODEL` 使用 `提供商:模型` 格式 |
| 进入教师页又回到入口 | 在 `/portal` 重新选择教师角色；本版无需PIN或访问码，若仍有口令弹窗，请确认部署版本已更新 |
| 换电脑后课程列表为空 | 检查共享存储配置及服务器是否已导入课程；本地模式请先导出再在目标环境导入 |
| 学生课堂链接被拒绝 | 使用当前服务器域名下的 `/classroom/课堂ID` 地址 |
| 可选 Dify 检索不可用 | 在设置中检查完整连接配置；在 Dify 中确认文档启用、索引完成，再调整检索词 |
| 声音、图像或视频不可用 | 检查对应服务和设置；首次音频播放可能需要点击，麦克风需浏览器授权 |
| 修改功能开关后页面无变化 | 重新启动开发服务；构建运行或 Docker 部署需重建 |
| 看板暂时没有数据 | 在当前学习者/课程下提交反馈或测试结果，再刷新对应范围的看板 |

建议的最小内测流程：启动 → 教师入口 → 创建或导入一门课堂 → 完成互动 → 刷新重新进入 → 导出成果 → 学生入口 → 提交反馈与查看看板。配置知识服务后再验证知识发布检索；配置共享存储后再验证跨浏览器访问。

## 源码结构

| 路径 | 内容 |
| --- | --- |
| `app/` | 页面、路由与服务端接口 |
| `components/` | 平台、备课、课堂、知识库与设置组件 |
| `lib/` | 模型接入、任务引擎、知识、记忆、存储与平台服务 |
| `packages/` | 课件 DSL、生成、导入、编辑、渲染、存储等内部包 |
| `skills/` | 内置教学技能及教师记忆应用规则 |

| `examples/` | 教学与实训案例素材 |
| `scripts/` | 案例生成、预检、内部包资源同步等工具 |
| `tests/`、`e2e/`、`eval/` | 定向测试、端到端测试与评测源码 |
| `render-service/` | 可选的独立视频渲染服务 |
| `.env.example`、`Dockerfile`、`docker-compose.yml` | 配置模板与部署入口 |

发行目录保留锁文件、内部包源码、部署文件、Skill 文件、示例和测试源码，以当前工作区文件为基准，包括本次发行时的未提交源码改动；排除 `attachment.md`、内部交接文件、Git 历史、个人配置、密钥、运行数据、依赖、缓存和构建输出。
