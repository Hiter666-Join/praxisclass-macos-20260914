## 入口与条件

本轮实际服务地址为 `http://localhost:3003`，使用原隔离数据和 `praxis_review_20260911` 数据库。下文所有相对路径均接在此地址后。评委在其他电脑操作时，由维护人填写其可访问的部署地址，并在该环境重新核对；本轮尚未验证远程部署。

1. 维护人先打开 `/portal`、`/teacher`、`/student` 和 `/api/stages`，确认页面或数据正常。仅 `/api/health` 成功不足以证明课堂存储可用。
2. 本机服务未启动时，由维护人确认 Docker 与原 PostgreSQL 容器可用，再从应用目录运行现有 `output/review-upgrade-20260911/start-native-review.ps1`。该脚本依赖本机既有隔离配置和本地代理，不作为其他机器的通用部署脚本；不要复制其中私有配置给体验者。
3. Chrome 中打开 `/portal`，直接选择教师或学生。无需注册、密码、PIN 或整站访问码。
4. 需要 Agent 的步骤，分别在教师页和学生页右上角“设置”中选择各自的模型、服务地址和密钥。两端分别保存；本书不提供、不记录密钥。换一个新浏览器配置文件后需要由操作者自行配置。
5. 主案例首次进入教师工作台，点“准备或继续主案例体验”。看到两段课堂、八份资料和方案第 1 版后再继续。此操作复用预制教学资源，并通过现有上传接口保存正文，不复制历史成绩或聊天。

## 记录方式

每次填写：日期与操作者代号、环境地址、浏览器是否全新、案例名称、任务编号、开始作答的方案版本、成果编号、当前输入、预期与实际差异、截图或反馈原文。截图避开密钥输入区域。

固定规则看相同输入是否得到相同结论。Agent 看是否实际读取所选正文、是否针对当前输入、是否引用可打开的依据；不同模型或重复调用可能使用不同措辞，不要求逐字复刻。服务失败应显示“未完成／待确认”，不能替换成学生能力失败。

新一轮建议在教师工作台点“创建新的演练任务”。保留先前任务和证据；不要清数据库、删浏览器数据或借用别人的密钥来“重置成绩”。本轮已用另一 Chrome 配置文件实测：新任务 `b3c22670-f209-4405-94e3-0e5d0e58e9d0` 从方案 1、零成果开始，八份原文可读，两端模型设置均为空；随后实际提交 A 并刷新回读。需要 Agent 时仍须分别配置两端服务。
