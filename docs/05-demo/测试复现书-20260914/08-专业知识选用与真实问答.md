# 专业知识选用与真实问答复现书

版本：SOFTWARE-KNOWLEDGE-1.0，2026-09-14本地接入。准备条件见[00](00-复现入口与准备.md)。本流程验证教师明确选用正文后，师生Agent按任务读取实际资料并回答问题；当前实现是上传正文与按编号取用，不声明已验证Dify、向量召回或搜索排名。

## 资料与角色准备

1. 进入教师工作台，新建本次选定案例。默认案例文件仍为主案例8份、代码7份、重试6份、视觉5份、仓储6份；它们是完成案例所需的共享正文，不包含教师答案键。
2. 在“本次使用的资料”中点击“选用本案例专业知识”。等待上传完成，核对下表文件及“学生可见”。此时只是加入草稿。
3. 填写调整理由，如“本次加入相关专业知识，供师生核对机制与边界”。点击“应用到本次实训”，看到新方案版本后再让学生开始。再次选择已在草稿中的同编号资料不会重复增加。
4. 在“本次资料与依据”点击新增文件，打开实际原文，核对KP条目、适用边界、依据编号和章节／页码。不能仅凭按钮或文件名出现认定正文可读。
5. 需要学生问答时点“以本次体验者进入”，打开同一正文，再使用对应成果下方的“学习Agent辅导”。两端服务各用当前设置。

| 案例 | 新增文件 | 条目范围 |
|---|---|---|
| 主案例 | 来源目录、HTTP、Spring接口、SpringAI与资料问答 | KP-001—032，共32条 |
| 代码验收 | 来源目录、代码验收与运行证据 | KP-033—042，共10条 |

跨主题合计52个唯一条目；同一HTTP文件被两组使用不重复计数。MD作为正文载体，未把相同JSON再次上传。教师专用的12题预期答案未上传给学生。来源目录用于定位，不把国家文件当成具体接口技术规范。源目录中离线PDF定位以同级原专业知识包为准，当前浏览器正文展示不代表完整PDF已在此页面内置。

## 可复制的12个问题

教师问题放入“教师Agent建议 → 需要调整的教学问题”；学生问题放入相应“学习Agent辅导 → 我卡在哪里”。点击“发送给Agent”，等待真实回执。

每组开头使用：

> 请实际读取本次选用的相关专业正文，按题号分别回答，并列出资料编号、正文内KP编号及适用边界。缺少依据时明确说明，不要编造产品功能、运行结果或修改教学安排。

### 主案例教师：Q1—Q4

```text
Q1：Content-Type和Accept分别描述什么，能互换吗？
Q2：HTTP返回200了，响应正文仍是needs_more_info，这算矛盾吗？
Q3：路径中的工单编号、query参数和JSON请求体，在Spring接口里分别怎么接？RequestParam只能处理query吗？
Q4：学生只有Java基础，没有网络课程经验，怎样用一个请求把客户端、HTTP、Java接口处理和响应串起来？
```

预期：区分请求／响应表示的媒体类型与可接受类型；区分协议状态与业务状态，并指出`needs_more_info`不在本案例契约的枚举中；正确说明三种参数读取及RequestParam可处理表单；从具体请求串联Java接收和返回，不能称为TCP三次握手或声称已运行Spring服务。

### 主案例学生：Q5—Q7

```text
Q5：检索到标题相似的产品文档，能直接证明目标产品2.0版支持自动归档吗？我还没提供目标版本文档。
Q6：本次选用的资料里找不到某项功能，能根据常识补成支持或者不支持吗？怎样让回答有证据边界？
Q7：Spring AI的Advisor就是一个自主Agent吗？如果能用ChatMemory，是否可以让不同学生共用一份对话记忆？
```

预期：相似度、标题与检索命中不证明功能适用；根据实际资料说明归档能力无法确认，缺失不等于不支持；提示策略不保证事实正确；Advisor扩展点与自主动作不同；应用负责学生／会话读取隔离，不把聊天当作产品证据。

### 代码验收教师：Q8—Q10

```text
Q8：bisect_left返回一个整数，为什么还不能直接认定找到了目标？不要读取或推测隐藏用例。
Q9：AI生成的代码能够运行，是否就说明满足需求？需求符合与功能测试应怎样留证据？
Q10：连续两次点击运行，如果回执先后次序颠倒，怎样知道哪个结果属于哪版代码？这又是否足以说明成果已保存？
```

预期：插入点需边界与相等性核对，并遵守最左匹配契约；能运行不等于符合需求；记录具体代码、输入、计划、环境、实际输出、运行及代码版本；结果绑定不能替代服务端保存回执。不得展开或猜测10条隐藏用例内容。

### 重试教师：Q11

```text
Q11：一次提交超时后重试，和明确要求再创建一张内容相同的工单，操作标识应如何处理？为什么不能只按相同参数来去重？如果只见超时，能否直接认定服务端没有创建？说明教学范围。
```

预期：同一意图重试沿用标识，新需求用新标识；参数相同不能判定意图相同；超时保留服务端未知状态；按调用者和操作标识去重并核对参数，注明串行、有效期及原子处理的教学假设。

### 仓储教师：Q12

```text
Q12：学生改变了质检阈值，或者把仓储任务条件由A期限改成B期限，能否复用旧的通过结论？在本仓储案例中条件应如何替换、需要补什么新证据？质检未给出具体样本和新阈值时，请勿编造新的数值结果。
```

预期：条件变化后建立对应新计算和结论；仓储取消A期限再改B≤1，先复核原最终顺序，再记录新选择。不能叠加条件，也不能编造未给输入的质检结果。

## 保存与核对

1. 记录每次回复下方“本次实际读取”的来源编号。回复文本中自称读过某资料，还需与该回执列表核对；正文KP编号再打开资料核对。
2. 刷新，确认该角色原回复与来源仍可回看。切换角色后不应在另一角色的辅导区出现这段私有对话。
3. 老成果继续绑定开始作答时的方案。对已开始的旧作答后来追加资料，不应悄悄改变它的冻结依据；想让新作答使用新增资料，应先准备并应用新的任务再进入学生侧。
4. 模型文字不要求逐字相同。只把有实际来源、符合边界的答案记为符合；未完成请求、来源缺失或数值编造分别登记。调用失败后保留当前输入，用“重试本次辅导”重试，不把失败当成学生能力不达标。
