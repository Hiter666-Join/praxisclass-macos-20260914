2. 点击“提交并查看反馈”，记下原文区域底部的成果编号，确认“已保存到服务端”。保存成功不代表开放回答已经达标。
3. 点击“重试同一次保存”，核对成果编号、原文和已保存份数不变。
4. 刷新浏览器，点“查看成果”，核对原文与编号一致；本机表单中的草稿不是唯一凭据。
5. 点“返回教师回看”，在当前任务选择“演练记录”，点“刷新成果”和对应成果。核对与学生看到的编号、版本、原文一致。

7. 学生如需更正，点“修改后再提交”，实际修改内容后提交。预期生成新的成果编号，旧成果可读，保留修订关系；内容未变时不应新增修订。

## 失败恢复

| 现象 | 操作 | 判定 |
|---|---|---|
| 网络返回不确定或页面说原文未确认 | 保留当前输入，重试同一次保存；也可刷新成果回读 | 原文、编号相同；不能新增一次“成绩”掩盖失败 |
| 原文已保存，AI 不可用 | 先回看已有规则结果，恢复当前端模型服务后重试评阅 | 不清空原文，AI 失败不记为能力失败 |
| 评价已保存、解释中断 | 点击“重试本次评阅”；刷新后仍可重试同一请求 | 使用中断前已核对的评阅补齐解释，不重新生成不同结论，已有评价不重复追加 |
| 原文与评价可读，但成果列表暂未同步 | 保留成果编号，重新打开本成果，再刷新成果列表 | 原文和已有规则结果保持可读，仅恢复列表状态；列表失败不能显示为学生评价失败 |
| 刷新后显示“重试本次评阅” | 使用当前角色设置重试，不更换成果或清浏览器数据 | 请求编号与会话编号不变，只补缺失步骤；服务设置从当前端读取，恢复记录不保存密钥 |
| 浏览器存储空间不足，评阅未能发送 | 由维护人恢复该浏览器的正常存储后，重试原按钮 | 未保存请求恢复信息时不启动模型调用，不能登记评阅完成 |
| 草稿或方案版本冲突 | 保留编辑内容，重新读取当前任务再决定调整 | 不静默覆盖别人的新版本 |
| 不同浏览器看不到原任务教师记录 | 使用自己的新任务，或由原教师打开所属任务 | 不能用另一个任务编号绕过所有者边界 |
