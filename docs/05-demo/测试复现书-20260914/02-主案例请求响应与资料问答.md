# 主案例：从一次请求到一个可信回答

版本：MAIN-TICKET-1.0。教学合成产品：TICKET-DEMO 2.0。案例主题是 Spring 请求响应与 Spring AI 资料问答；平台本身未因此改写为 Spring AI 技术栈。验证日期：2026-09-14。

## 准备主案例

1. 完成[环境与两端设置](00-复现入口与准备.md)，在教师工作台点“准备或继续主案例体验”。
2. 等待八份正文上传完成，进入“从一次请求到一个可信回答”，看到方案第 1 版、两段活动入口和资料按钮。
3. 在“本次资料与依据”点击 `02-HTTP与Spring技术说明.md`、`05-接口约定.md`，确认能读到正文，而非仅看到本机路径。教师参考默认不向学生公开；本次八份共享正文已明确选为学生可见。
4. 初次上传失败可重试同一按钮；已完成的上传继续复用。本轮修复过 Windows 匿名所有者目录中的冒号问题，修复后八份原文已实际上传成功。

本轮任务编号 `1074044f-a2e8-41f9-9251-b577374e7daa`；新体验会生成不同编号。不要把本轮固定链接当作新浏览器的教师所有权凭据。

## 教师局部调整与真实 Agent

在“教师 Agent 建议”输入：

> 本班学过 Java，但把浏览器显示“请求已提交”和后端 HTTP 200 混为一谈，也不知道 question 字段如何对应输入。请读取本次 HTTP 技术说明和接口约定，帮我把第一段课堂的教学支持调整为一次有明确输入和检查点的渐进练习，保留 A/B 成果与原评价规则。请给出可填入草稿的局部建议。

点击“发送给 Agent”。预期：本次实际读取的来源包含 TECH-HTTP、CONTRACT-MAIN，返回可填入草稿的建议；尚无新成果时不能声称已经看到学生提交。点击“填入调整草稿”，核对学情、支持内容和调整理由，再点“应用到本次实训”。本轮实际生成并应用为第 2 版；这是教师确认，不是 Agent 自动改课。

点击“以本次体验者进入”。学生看到应用后的教学支持；教师私有学情字段不直接下发。

## 学生辅导与 A 活动

在 A 下方“学习 Agent 辅导”输入：

> 我知道 Java 对象有字段，但不明白页面上的问题文字怎样进入后端的 question；收到 200 就能说答案有依据了吗？请只给我下一步检查方法，不替我选 A 题答案。

预期：学生侧使用学生自己的当前配置，实际读 TECH-HTTP、CONTRACT-MAIN，提供对应检查方法。回复不是 A 的已提交成绩。

进入“请求响应图解与字段对应练习，随后完成 A 验证”：

| 操作 | 本轮输入／选择 | 预期 |
|---|---|---|
| 输入新问题 | `P1-0243：我的账号忘记密码，应怎样处理？`；复测可换自己的唯一标记 | 当前问题保留在输入框 |
| 选择错误字段并点“查看本次对应” | `answer` | 指出本次请求缺少 question |
| 改字段后再点 | `question` | JSON 中 question 包含刚才的新问题；说明其对应后端字段 |

用浏览器后退回本次任务，填写成果 A：A-C1 选第 1 项；A-C2 选第 1、2 项；A-C3 选第 1、2、4 项。点击“提交并查看反馈”。预期三项规则满足，“接口理解：已达标”，原文已保存到服务端。再点“重试同一次保存”，不增加另一份成果。

## B 活动与开放回答

进入“资料适用性图解与练习，随后完成 B 验证”：

| 当前选择 | 预期 |
|---|---|
| 2.0、普通成员导出、D2 | D2 的 1.0 管理员说明不能用于当前 2.0 问题 |
| 改为 D1 | 2.0 普通成员不开放上述 CSV 导出入口 |
| 保留 D1，问题改为忘记密码 | 版本相同仍不代表段落能支持密码重置结论 |
| 密码问题改用 D3 | D3 明确覆盖 1.0 和 2.0，不能仅因为同时涉及旧版就排除 |

回到任务填写 B。B-C1 选择前两项流程；其余字段必须填写当前自己的结论、所用文档与段落、理由，再提交。固定流程选择先独立评价，开放回答先保留待确认。点击所选成果下的“评阅本次开放回答”，Agent 必须读取本次已保存原文和相关资料，才能保存评阅与解释。

以下是本轮可重复输入。B-3 第一稿刻意包含边界错误，用于核对反馈，不能作为学生参考答案或真实学生统计。

| 字段 | 第一稿输入 |
|---|---|
| 核验候选资料的一句话 | 先核对产品、版本、账号角色，再读对应段落是否明确支持准备给出的结论；相似度高本身不能替代适用性和支撑关系核验。 |
| B-1 结论 | 管理员在工单列表设置本月日期范围后，点击导出CSV，导出该日期范围内的工单记录。 |
| B-1 依据 | D1 §4.1 |
| B-1 理由 | D1 §4.1 明确适用于 TICKET-DEMO 2.0 管理员，并说明按所设置的日期范围导出。 |
| B-2 结论 | 这个引用不能支持 2.0 只能导出当前页。应使用 D1 §4.1，说明 2.0 管理员可以导出设置日期范围内的记录。 |
| B-2 依据 | D2 §4.1 与 D1 §4.1 |
| B-2 理由 | D2 仅适用于1.0；将旧版本当前页的限制直接用于2.0，缺少版本适用性依据。 |
| B-3 结论（刻意错误） | 不支持每天定时导出和自动邮件发送。 |
| B-3 依据 | D1 §4.1；本次未找到定时导出与邮件功能的明确说明。 |
| B-3 理由（刻意错误） | D1只写了手动导出，没有写到定时邮件功能，所以可以确定产品不支持。此处是开发者刻意提交的边界错误，用于检验反馈，不代表真实学生表现。 |
| 可选迁移 | 可以使用 D3 §2.1：该资料明确覆盖1.0和2.0的账号重置，范围与问题对应，不能仅因涉及旧版就排除。 |

预期：提交后固定流程选择满足，开放回答待评阅。实际 Agent 评阅后，流程说明、B-1、B-2 满足，B-3 需修改，证据判断显示“需加强”；不能将“未说明”判成原文明示不支持。保存的第一稿编号为 `48ccc4a9-9883-4f9f-af20-13e0db1a6ff5`，绑定方案 2。

## 教师根据本次成果调整，学生修订

1. 刷新学生页，回读 B；点“返回教师回看”，选择相同成果编号，核对原文和评价一致。
2. 在教师 Agent 输入以下内容，把其中“本次 B 成果编号”替换为自己页面的编号：

> 请先读取本次 B 成果编号的原文和评价。这是开发者演练，B-3 把“资料没有说明”推成“产品不支持”。请结合本次资料，只为 B 段新增教学支持，加入对未知、明确否定和资料读取失败的比较检查，保留 A/B 成果与原评价规则，并用该成果编号登记调整依据。不要把这次演练说成真实学生统计。

3. 点击“发送给 Agent”，等待实际读取成果与资料。点“填入调整草稿”，核对新增内容接在原有教学支持之后，A 段原文仍在，再点“应用到本次实训”。新方案应记录本次成果编号作为依据；旧成果仍绑定开始作答时的方案。
4. 切换学生，在 B 点“修改后再提交”。其余答案保留，将 B-3 三个字段改为：

| 字段 | 修订稿输入 |
|---|---|
| B-3 结论 | 现有资料无法确认是否支持每天定时导出并自动通过邮件发送，需要补充 TICKET-DEMO 2.0 定时任务及邮件通知相关说明。 |
| B-3 依据 | D1 §4.1、D2 §4.1、D3 §2.1 均没有足够依据确认该功能；D1适用于2.0手动导出，D2为1.0说明，D3说明账号重置。 |
| B-3 理由 | 本次已能读取资料，但其内容未覆盖定时导出和邮件功能；未说明不能推断支持，也不能推断不支持。这与资料读取失败、以及原文明示不开放某权限是不同情况。需取得相关功能说明后再判断。 |

5. 提交后记下新编号，点击“评阅本次开放回答”。预期 B-3 满足、证据判断“已达标”；保留旧稿及修订关系。若模型结论不同，核对实际引用与解释并登记差异，不改写记录冒充通过。
6. 刷新后分别回看 A、B 第一稿、B 修订稿，再返回教师逐份核对。当前应有三份成果，两端对同一成果显示相同原文；第一稿错误和原评价仍然可读。

本轮修订稿为 `7c957a16-b425-49c3-8fdc-351ac034a333`，修订自 `48ccc4a9-9883-4f9f-af20-13e0db1a6ff5`，仍绑定作答时的方案 2。本轮当前教学方案为第 5 版：第 3 版走查发现旧入口用完整文本替换教学支持，随后修复为仅追加建议；第 4 版恢复原 A 内容，第 5 版通过真实 Agent 再次验证追加。上述工程修复历史保留，正常复现无需执行修复脚本，也不要求新任务达到相同版本号。

## 无模型时手动调整教学支持（新增入口，待浏览器补验）

没有配置模型时仍可完成免密入口、资料阅读、A/B正式保存及教师手动调整。开放回答保持“待确认”，不能写成AI评阅通过。

1. 新任务方案1时，在“学情”填写“已学Java，尚未理解question字段映射、HTTP成功与答案有依据的区别”。在“本次教学支持”原内容后追加：“先逐项指出输入框、question字段与返回状态；再分别核对资料版本、角色和具体段落。”在“调整理由”填写“新浏览器开发者演练：为初学者补充检查顺序”，点“应用到本次实训”，预期生成方案2。
2. 按本书A及B步骤填写并保存两份当前成果，记下各自编号。B不调用模型时，固定选择结果保留、开放回答待确认；与上文真实Agent结果分开登记。
3. 返回教师，打开本次B原文，点新增的“将本成果作为调整依据”。预期焦点回到“本次教学支持”，出现“本次调整依据：1份已保存成果”；重复点击同一成果不增加份数。如选错可点“清除成果依据”后重选。
4. 在原教学支持后追加：“针对这份B-3说明，分别写出明确否定、资料未覆盖、资料读取失败三种情况的下一步。”调整理由写“依据本次B原文补充证据边界检查”，应用为方案3。
5. 刷新后分别回看A/B。旧成果仍绑定方案2，原文不变；新方案保留原支持内容和B成果依据。需要AI时，由操作者各自在两端设置服务，再走上文真实Agent步骤，不复制其他浏览器密钥。
